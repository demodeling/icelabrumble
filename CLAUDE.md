# CLAUDE.md — house rules for working on IceLab Rumble

## What this is
A single-page HTML5 canvas fighting game (the IceLab crew vs a false-positive rhino), deployed to GitHub Pages by the workflow in `.github/workflows/pages.yml`.

## Layout
- `src/index.html` — the whole game (CSS + JS in one file). The tokens `__VIDEOS__`, `__APPVER__` (package.json version, shown on the title screen) and `__VERSION__` (git hash) are replaced by `tools/build.py`; never hardcode them. Bump `"version"` in `package.json` when releasing.
- `src/vendor/trystero.js` — Trystero (WebRTC + Nostr signalling) bundled as one ES module for co-op; regenerate with `npm run vendor`. Imported on demand by `netTransport()`.
- `src/sw.js`, `src/manifest.webmanifest`, `src/icons/` — installable web-app bits. `__VERSION__` in sw.js is replaced at build time. The page, scripts and manifest are network-first (cache = offline fallback); videos/icons cache-first. The page reloads itself once when a new worker takes over while on the title screen. Fullscreen: native Fullscreen API where it exists (iPhone from iOS 16.4) with a landscape lock attempt, CSS rotation (`fs-rot`) as the portrait fallback; iPhones not installed as an app get a Home Screen hint on the title screen.
- `assets/videos/intro.mp4` — the only clip: the menu video ("False positive: a real sequence, the wrong label", rhino turns into a zebra) from `tools/video/render_intro.sh` (`CHAR` = a roster id, `SHIRT` = its jacket colour; the sprites come from `node export_sprites.js <id>`). `tools/build.py` copies `CLIPS` = `['intro']`. There are no per-fighter videos — do not add any.
- `tools/build.py` — assembles `dist/`. `--inline` embeds the menu clip as base64 (single-file build for claude.ai artifacts).
- `tests/smoke.spec.js` — Playwright smoke test. Keep it green.

## How to work
1. `npm install && npx playwright install chromium` once.
2. Edit `src/index.html`. Run `npm test` (builds, then tests). Run `npm run serve` and open http://localhost:8000 to play.
3. Commit to `main` and push; the Action tests, builds and deploys. The live site updates in 1–2 minutes.

## Rules of thumb
- Safari first: no optional chaining or `??` in page JS, Web Audio only after a user gesture (`unlockAudio()`), pointer events for touch buttons.
- Keep `dist/` out of git; it is a build product. `docs/` IS committed: it is the pre-built copy for branch-based GitHub Pages — rebuild it with `python3 tools/build.py --docs` when you change `src/`.
- Levels live in the `LEVELS` array (theme, rhino HP, `mutant` behaviours, intro card text); `LEVEL` is the current index. Round 2 = wasteland theme, feints, hot spots, radiation burst, CRT overlay. Round 3 = space theme (`gravity: .5`), horn laser bolts (`bolts`), jet-stomp with landing ring, helmets. Round 5 = `reruns: 4`: the pacifist reveal chains (see below). Round 6 = `depth: true`: the arena gets a z axis — `Z3` (vanishing point + focal length), `zScale(z)` = `f/(f+z)`, `zPoint(x, z, y)` for floor points, `withZ(z, fn)` draws any 2D rig as a billboard at that depth with distance haze, `drawFloor3D()` lays the ice plane and its grid and `drawLane3D(r)` telegraphs the charge. The rhino's `z` drives the states `zback` → `zaim` → `zcharge` (straight at the camera, dodge sideways or jump); `inReach(r)` (z ≤ 70) gates every attack, including the area specials, and `packR`/`unpackR` carry `z` for co-op. Round 4 = two rhinos (`rhinos: 2`, PCR duplicates) on a field twice as wide (`width: 1920`): `AW` is the arena width, `camX` the camera (follows the fighters, `updateCamera()`), the world layer is translated by `-camX` in `draw()` and the background scrolls at half speed; `G.rhinos` is the array (`G.r` = the first), `liveRhinos()` / `rhinoAt(pt, pad)` / `nearestRhino(x)` for hits, `hitRhino(r, p, …)`, `updateRhino(r, dt)`, one HUD bar per rhino, the round is won when every rhino is gone.
- Pacifist ending: survive `pacifistTime()` (30 s, per stage — `G.stageT`, not `G.elapsed`) with zero hits landed and `rhinoReveal()` turns the rhino into a tapir/horse/zebra (`ANIMALS`, states `morph` → `graze` → `trot`).
- Round 5 chains that: `revealKinds()` adds the species with `belongs: true` (reindeer, moose, arctic fox, wolverine, brown bear, lynx, mountain hare — things that belong in a Kiruna sample) and more that do not (camel, okapi, warthog). A `belongs` species, or the `reruns`-th pass, ends the round (`G.identified` picks the result text); anything else sets `r.rerun`, and `graze` hands over to `rhinoRerun()`, which puts the fight back and resets `G.stageT`. Landing a hit ends the chain and the round becomes an ordinary KO fight.
- Debug hooks in the URL hash: `#pacifist=<seconds>` shortens the timer, `#reveal=<kind>` forces the species, and `window.__fight()` reports `{spawns, over, pacifist, identified, stageT}` for the tests.
- Fighters are the people on the [IceLab members page](https://www.umu.se/en/icelab/about-us/members/): the `MEMBERS` table (`[id, name, role, group, theme]`, page order: group leaders, members, affiliated researchers) drives `ROSTER`. One signature move per research `theme` in `THEMES`, stats from `hashOf(id)` + `KINDMOD`, and the paper-cutout face from `lookFor(id)`: a hash-generated look, overridden per person by `LOOK_FIX[id]` (hair, glasses, beard and tone read off the public staff photos on the members page — reference only, never stored). Group leaders and members are pinned; affiliated researchers are still on the hash. Specials are in `specialUpdate()`; rhino behaviour in `updateRhino()`.
- `#credits` is the CREDITS screen off the title (what IceLab is and why it is great, the roster count filled in by `openCredits()`, and the note that the faces are cartoons rather than portraits).
- Adding a fighter: a `MEMBERS` row (and a `THEMES` entry if the research theme is new) + the roster count in `tests/smoke.spec.js`. The roster grid also holds group headings, so tests select fighters with `.fighter` + `nth(i)`, never `nth-child`.
- Co-op: `Net` + `coopJoin()` / `netData()` (host = lower peer id). The host runs `hostTick()` → `update()` with `G.players` = [host, guest] (guest inputs arrive as `{t:'in'}`), and `sendSnap()` every 2nd frame; the guest runs `guestTick()` and `applySnap()`. Sounds are relayed through `Net.sfxQ`. Two paths: Trystero (`TRYSTERO_URL` = `./vendor/trystero.js`, imported on demand, `relayConfig.redundancy` 10, optional `TURN_SERVERS` / `TURN_CREDENTIALS_URL`) and `relayTransport()` = Supabase Realtime broadcast + presence on the project's `/realtime/v1/websocket` (Phoenix protocol, channel `swebits-rumble:<code>`). `sendNet()` goes P2P when `Net.rtcUp`, else via the relay; the lobby always runs on the relay; every message carries `from` = own id (`setPeer()` does host election). The fighter-screen line shows nostr relays, relay state, the path in use and join errors. Tests inject `window.__coopTransport` (`noRelay: true` to skip the relay) and mock the relay with `page.routeWebSocket`. Anything that hits or targets a player must loop over `G.players` (see `rhinoTarget()`, `hitPlayer(p, …)`).
- Scores: `Scores` adapter (`load()` / `add(entry)` / `report(entry)`) talks to the Supabase `icelab_scores` table via REST (`SUPA` constants; schema in `supabase/migrations/`, insert-only under RLS, `report_icelab_score()` hides an entry). It is this game's own table — the older `scores` table belongs to the Swebits build and is left alone; `fighter` holds full names, so it allows 48 characters. localStorage is the fallback when the table is unreachable. `board` caches the last list for the title-screen best and the roster cards.
- Never commit photos of people to the repo; the cutout faces are drawn in code on purpose. Reading hair/glasses/beard off a public staff photo into a `LOOK_FIX` entry is fine — saving the image is not.
- Roster ids are slugs of the names (`martin-rosvall`), not staff-page URLs; they seed the stats hash and name the sprite files.
